Stop paying for walls of context

pxpipe turns long prompts, tool output and old history into dense images, so Claude Code and Fable 5 read the same context for far fewer input tokens.

Adi2 min read

Image tokens are priced by pixel size, not by how much text is drawn on the image. In the repo's example, about 48k characters (roughly 25k text tokens) fit on one image billed at about 2.7k tokens.

What pxpipe does

pxpipe-proxy runs locally between Claude Code and the Anthropic API. It finds large input blocks worth compressing, renders them as PNG pages and forwards the request. Recent turns stay as text, and replies stream back unchanged.

Start the proxy

Run the proxy, then point Claude Code at it.

The dashboard at http://127.0.0.1:47821/ shows every conversion and the tokens saved. Its kill switch sends everything as plain text again.

Run · Bash
# Start the proxy on 127.0.0.1:47821
npx pxpipe-proxy

# In a second terminal, route Claude Code through it
ANTHROPIC_BASE_URL=http://127.0.0.1:47821 claude

What gets rendered

Only the large, repetitive input. Everything else passes through as text, including model output and requests to unsupported models.

As imagesLarge tool output, older history, the system prompt and tool docs
As textRecent messages, short messages, exact IDs, hashes and secrets

The catch

Models read images as pixels, not guaranteed characters. Imaged context is good for gist, code structure, logs and docs, but unreliable for exact strings.

Keep hashes, IDs, filenames and secrets as text, or have the agent re-read the source before acting on them. The repo reports 59–70% lower cost on its Claude Code workloads; savings depend on your workload.
