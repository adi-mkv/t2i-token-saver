How To Stop Wasting Tokens On Walls Of Context

A quick tutorial for using pxpipe with Claude Code and Fable 5: turn bulky prompts, tool docs, and old history into dense images so the model can read more context for fewer input tokens.

Adi 3 min read  ·  July 2026

If you use Claude Code with Fable 5, there is a clever way to stop burning input tokens on giant chunks of repeated context. Instead of sending every long prompt, tool dump, file read, and older history block as plain text, pxpipe renders the bulky parts into compact PNG pages before the request leaves your machine.

The trick works because image token cost is based mostly on pixel size, not the amount of text drawn inside the image. The repo shows an example where roughly 48k characters, about 25k text tokens, become a dense image page billed at about 2.7k image tokens. That is the whole idea: use the model's vision channel as a cheaper carrier for context that does not need to be byte-perfect.

What Is pxpipe

GitHub repo README

pxpipe-proxy is a local proxy for model requests. Claude Code sends its Anthropic traffic to the proxy, the proxy looks for token-dense input blocks that are worth compressing, renders those blocks as images, then forwards the transformed request. The model output still streams normally. Your recent turns still stay as text. The proxy only compresses eligible input bulk.

Start The Proxy

The fastest path is a two-command setup. First run the proxy. Then point Claude Code at the local Anthropic-compatible endpoint. The dashboard opens on the same port so you can inspect what was converted, watch savings, and hit the kill switch if you want everything to pass through as plain text.

RUN 
npx pxpipe-proxy                                  # proxy on 127.0.0.1:47821
ANTHROPIC_BASE_URL=http://127.0.0.1:47821 claude  # route Claude Code through pxpipe

Once it is running, visit http://127.0.0.1:47821/. You will see each text-to-image conversion side by side, the current model allowlist, and the measured token counterfactuals logged by the proxy.

What Gets Rendered

pxpipe does not blindly turn the whole chat into screenshots. It targets the expensive, repetitive input: large tool results, older collapsed history, and the static system prompt plus tool docs slab. Small messages, recent context, sparse prose, model output, and unsupported models pass through normally.

MENTAL MODEL 
model request
  - recent user messages: keep as text
  - exact IDs, hashes, secrets: keep as text
  - huge tool output: render as PNG pages when profitable
  - old history: render as PNG pages when profitable
  - system prompt + tool docs: render as PNG pages when profitable

proxy forwards transformed request
model reads image pages through vision
response streams back untouched

The Catch

This is not OCR. Vision models read pixels as embeddings, not as guaranteed characters. That means dense imaged context is great for gist, code shape, logs, repeated docs, and broad recall, but it is risky for byte-exact strings. If the task depends on a hash, a short ID, a filename, a secret, or a tiny value where one character matters, keep that part as text or make the agent re-read the source file before acting.

That is the trade: you can often cut request cost dramatically, sometimes around 59 to 70 percent end to end on Claude Code style workloads, but the savings come from using a lossy channel. Use it for bulky context. Do not use it as your only copy of facts that must be reproduced exactly.
